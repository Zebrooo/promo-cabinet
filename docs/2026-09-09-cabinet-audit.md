# Критический разбор промо-кабинета: что убрали, что добавили, что отвергли

- **Дата:** 2026-09-09
- **Репозиторий:** promo-cabinet (только он; BFF и витрина не трогались)

## 1. Как смотрели

Прошли весь кабинет глазами админа: список → создание → редактирование →
очереди → остальные разделы. Отдельно прогнали автоматический поиск мёртвого
кода (неиспользуемые экспорты, зависимости, CSS, роуты, страницы вне навигации).
Каждое предложение затем проверили с другой стороны: есть ли уже решение
владельца по этому месту в истории коммитов и спеках, что сломается, чем
докажем пользу. Ниже — и принятые, и отброшенные.

## 2. Сделано

### 2.1 Убраны выдуманные цифры из редактора

В правой колонке редактора висел блок «ОЦЕНКА ОХВАТА ~ 4 200 / день · на
основе 30-дневного трафика» и «СЛОТ popup · feed-top». Оба — константы в коде
(`estimateReach` по формату, строка `feed-top` для любого промо), к трафику и
очередям отношения не имели; комментарий в коде с мая обещал «заменить на
реальные CTR». Заголовок редактирования показывал «обновлено 14:32» — просто
текущее время рендера, не время правки промо (в пуле нет `updatedAt`).

Проверка: владелец уже вычищал такие же фейки из списка в #35 («v2.4.1»,
«ОБНОВЛЕНО HH:MM») — решение согласуется. Реальные показы остаются в блоке
над формой (PromoAnalyticsBlock), очереди — в секции «Очереди показа».

### 2.2 Ошибка сохранения видна там, где нажали

Кнопка «Сохранить» — в липкой панели сверху, а баннер «Проверьте поля формы»
рендерился в самом низу колонки, под таргетингом, то есть за экраном.
Теперь ошибка показывается строкой прямо в липкой панели, а страница
прокручивается к первому полю с ошибкой (`scrollToFirstFieldError`,
класс `ef-field-error` у `FieldError`). То же — в форме пуш-рассылок.

### 2.3 После создания — на страницу промо, а не в список

Очереди назначаются только после первого сохранения (чипы в «Очереди
показа» в режиме создания выключены), а без очереди витрина промо не
покажет — в списке это даже подсвечено предупреждением «Не в очереди».
Раньше после «Сохранить» кабинет уводил в список, и промо приходилось
искать и открывать заново. Теперь создание ведёт на `/cabinet/<id>?created=1`
с плашкой «Промо создано. Теперь добавьте его в очереди показа». Параметр
убирается из адреса после показа. Сохранение правок по-прежнему ведёт в список.

### 2.4 «Дублировать» промо

Формат и устройство после создания менять нельзя, таргетинг — десятки
полей: сделать «такое же, но для другого раздела/дат» означало перебить
всё руками. Кнопка «Дублировать» в редакторе открывает `/cabinet/new?from=<id>`
с копией контента, таргетинга и лимитов, свободным id (`<id>-copy`,
`-copy-2`, …) и пометкой «(копия)» в названии (`lib/duplicate-promo.ts`,
покрыто тестами). Очереди не копируются — их назначают после сохранения,
как у любого нового промо. Для `referral-invite` кнопки нет: это
config-синглтон, вторая копия перезаписала бы те же настройки витрины.

### 2.5 Защита от потери несохранённой формы

Закрытие вкладки / F5 при изменённой форме спрашивают подтверждение
(`beforeunload` по Formik `dirty`); ссылка «← Вернуться к списку» и
«Дублировать» при несохранённых правках показывают `confirm`. Клиентские
переходы по боковой навигации не перехватываются — это осознанное
ограничение, а не баг: цена ложных срабатываний там выше.

### 2.6 Мобильные табы

Сетка нижних табов была `repeat(6, 1fr)` при семи пунктах (после разделов
«Кампании» и «Push-рассылки» в #39/#40) — седьмой таб уезжал во вторую
строку в 56-пиксельной панели. Теперь колонка на каждый таб автоматически.

### 2.7 Мёртвый код

- удалён шим `components/PromoForm.tsx` (два импорта переведены на
  `promo-form/PromoForm`);
- удалены `poolSchema` (алиас `catalogueSchema` без единого использования) и
  тип `PushCampaignStatus`;
- из стилей редактора удалены `.ef-image-preview/-thumb/-meta`, `.ef-divider`,
  `.prev-foot/-slot/-reach/-reach-sub`, `.ef-error` — ни на один нет ссылок.

## 3. Проверено и отвергнуто

| Предложение | Почему нет |
| --- | --- |
| Убрать зависимость `@divkitframework/divkit` (в `src/` не импортируется) | Это peer-зависимость `@zebrooo/promo-renderer` (`pnpm-lock.yaml`), без неё ломается превью DivKit. Первый кандидат аудита оказался ложным. |
| Вернуть клики/CTR в блок показов на странице промо (данные в `getPromoTimeline` уже есть) | Решение владельца в #3: продуктовая аналитика — только в Яндекс.Метрике, в кабинете лишь счётчик показов. |
| Убрать самотелеметрию кабинета (`AutoClickTracker`, `/api/track` → BFF) | Это не мусор: её специально защищали в #37 и описали в `docs/event-taxonomy.md`. Нужность — продуктовый вопрос к владельцу, не технический. |
| Переставить пункты навигации (промо/очереди/лиды вместе) | Косметика, ломает привычку единственного пользователя, пользы не докажем. |
| Убрать выключенную карточку «Grafana прод — ещё не поднята» в «Метриках» | Заглушки там намеренно, как план (комментарий в `metrics/page.tsx`). |
| Разрешить выбор очередей прямо при создании | Даёт частичные отказы (промо сохранилось, очередь — нет) и второй путь записи членства; переход на страницу промо (2.3) закрывает боль без нового состояния. |
| Снять `export` с ~70 внутримодульных символов | Механическая правка без пользы для пользователя, риск задеть test-only экспорты. |
| Переименовать «persist / не persist» у очередей | Форма создания очереди уже объясняет термин, пользователь технический. |
