# Редизайн «Расширенных настроек» промо-редактора

Дата: 2026-08-18 · Статус: согласован с владельцем (вариант A из трёх)

## Проблема

Сейчас «Расширенные настройки» — один disclosure-блок в PromoForm, внутри
которого подряд ~35 полей: ID/название, даты показа, лимиты показов и весь
таргетинг (возраст, регионы, подписки, поиск, покупки, кошелёк, объявления
продавца, разделы/категории, аудитория, ОС/среда/класс устройства).

Боли (подтверждены владельцем, все четыре):
1. простыня полей одной колонкой — трудно найти нужное;
2. не видно, какие фильтры реально включены (особенно в свёрнутом виде);
3. базовые вещи (ID, название, даты) свалены вместе с таргетингом;
4. сами поля неудобны (слаги через запятую, копейки/рубли, подсказки-титлы).

По бэклогу запланировано ещё ~19 таргетингов (гео, интересы, dayparting…) —
владелец подтвердил: структура должна закладывать этот рост.

## Решение (вариант A — «подключаемые фильтры»)

Секция «Расширенные настройки» удаляется целиком. Её содержимое
перераспределяется:

### 1. Новая секция «Основное»

Сразу после «Где показывать / тип промо», до «Контента». Поля из
ScheduleSection без изменений поведения: ID (slug, disabled в edit-режиме),
внутреннее название, начало/окончание показа.

### 2. «Цепочка показов» → «Показы и лимиты»

К существующему чекбоксу цепочки (`afterPromoId` + datalist) добавляются два
поля из FrequencyCapFields: лимит показов на пользователя
(`maxImpressionsPerUser`) и кулдаун в часах (`cooldownHours`).

### 3. Новая секция «Таргетинг» — подключаемые фильтры

Паттерн рекламных кабинетов: по умолчанию видны только включённые фильтры,
остальные добавляются по одному из каталога.

**Реестр фильтров** — единый описатель, по одному на фильтр:

| Поле реестра | Смысл |
|---|---|
| `id` | стабильный ключ фильтра |
| `label` | название в карточке и каталоге |
| `group` | группа каталога |
| `isActive(values)` | активен ли фильтр (есть непустые значения) |
| `summary(values)` | человекочитаемая сводка («от 25 до 45», «iOS, Android») |
| `clear(setFieldValue)` | очистка всех значений фильтра |
| `Editor` | компонент полей фильтра (рендерится в развёрнутой карточке) |

**Состав каталога** (текущие поля, сгруппированы):

- **Аудитория:** Возраст (`targeting.minAge/maxAge`), Регионы
  (`targeting.regions`), Уровень подписки (`targeting.subscriptionLevels`),
  Гости/залогиненные (`audience`), Продавцы/покупатели (`sellerStatus`).
- **Поведение:** Поиск (`targeting.search`), Покупки пакетов
  (`targeting.purchases`), Объявления продавца (`targeting.listings`).
- **Деньги:** Кошелёк (`targeting.balance`).
- **Устройство и среда:** ОС (`targeting.os`), Среда
  (`targeting.environments`), Класс устройства (`targeting.deviceBrands`).
- **Контекст страницы:** Разделы (`sections`, пометка «только overlay»),
  Категории (`categories`).

Будущие таргетинги из бэклога = новая запись в реестре, форма не растёт.

**Поведение карточки фильтра:**

- свёрнута: название + сводка из `summary()` + кнопки «изменить»/«✕»;
- клик (или «изменить») разворачивает редактор на месте, без модалок;
- «✕» убирает карточку и вызывает `clear()`;
- новый фильтр добавляется сразу развёрнутым;
- список добавленных = фильтры с `isActive(values)` + добавленные в этой
  сессии, но ещё пустые (локальный UI-state; при загрузке существующего
  промо карточки строятся из значений).

**Каталог «+ Добавить фильтр»:** выпадающая панель с поиском по названию и
группами; уже добавленные фильтры показываются задизейбленными с пометкой
«уже добавлен». Пустое состояние секции: «Фильтров нет — промо показывается
всем».

### 4. Что переносится без изменений

Подсказки и ограничения текущих полей сохраняются внутри редакторов фильтров:
premium-подписка задизейблена (биллинг не отдаёт), предупреждение про
`none`-подписку и гостей, хинты про lookback-периоды, warning про overlay-only
разделы.

## Что НЕ меняется

- Схема `Promo`, `toPersisted`/`toPreview`, `validate`, API и BFF — редизайн
  чисто UI-перекомпоновка; сохранённые промо открываются как раньше
  (карточки строятся из значений).
- Секции «Где показывать», «Контент», «Очереди показа», превью-рейл.
- Мелкие улучшения полей (боль №4) — отдельными точечными правками внутри
  редакторов фильтров, без изменения формата данных: рубли вместо копеек уже
  конвертируются на границе инпута, слаги остаются comma-list (SlugListField),
  title-подсказки станут видимыми `ef-hint`.

## Ошибки и валидация

`FieldError`-ы переезжают внутрь редакторов фильтров как есть. Сабмит с
ошибкой в свёрнутой карточке: карточка с ошибкой автоматически
разворачивается (иначе ошибку не видно) — это единственное новое поведение
валидации.

## Тестирование

- Юнит-тесты реестра: для каждого фильтра `isActive`/`summary`/`clear`
  согласованы (после `clear` фильтр неактивен; активный даёт непустую сводку).
- Интеракционные тесты секции: добавление фильтра из каталога, удаление с
  очисткой значений, автораскрытие карточки с ошибкой при сабмите.
- Существующие тесты (`to-persisted`, `validate`, `submit-touched`) не
  трогаем — данные не меняются.

## Вне скоупа

- Новые таргетинги из бэклога (только место под них).
- Изменения схемы/BFF/чекеров.
- Редизайн остальных секций формы.
